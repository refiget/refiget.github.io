学习笔记

ADT Summary

发布时间：2026年10月27日

cs61b 的前半部份，数据结构也接近尾声了，这里我就对我学过的内容，做一些总结和回顾吧。

首先课程的一个核心的想法就是，我们使用的数据结构是 ADT，即抽象的。我们 user，不用关注其特性，我们只关注它的行为是否符合预期。比如有一个数据结构，只要可以实现 LIFO，我们就可以将其视为 stack，而不需要在意背后的实现逻辑。

我们第一个学的 ADT 是 List，开始我们的要求也非常简单：

  • addFirst(x)：在开头插入元素。
  • addLast(x)：在末尾插入元素。
  • insert(i, x)：在指定位置插入元素。
  • getFirst()：获取第一个元素。
  • getLast()：获取最后一个元素。
  • get(i)：获取指定位置的元素。
  • removeFirst()：删除并返回第一个元素。
  • removeLast()：删除并返回最后一个元素。
  • size()：返回元素数量。

最自然的想法就是定义一个 IntList，其 instance variables 包含 item 和 next。其开始的节点就代表 IntList 整体。

我们只能从它有且仅有的 next 属性构造所有剩下的方法，这里涉及对第一个元素的都是 O(1)O(1) 的，涉及任一个或者最后一个节点的都是 O(n)O(n)。size()基于实现，牺牲空间就是 0(1)0(1)，调用的时候计算就是 O(n)O(n)。

接下来的升级就是将 IntList 封装起来，外部类 SLList 作为一个外部类保存 first 的 ref。内部 IntList 封装为 IntNode 作为节点。这样我们就不需要用一个节点代表 IntList，而是把它单独封装为一个类，虽然都是基于第一个元素。

还有一个好处就是，IntList 版本，addFirst 等方法，因为面临的对象本身就是节点，也就是我们需要说明 xx 对象在 xx 对象的第一个位置插入 xx 元素，即 l1.addFirst(3, l2)。这显然不符合用户直觉呀，作为用户，我们期待的操作是应该是类似“往袋子里放一个东西”而非“袋子里的物品旁边放一个东西”。封装后，我们可以直接 l1.addFisrt(3)，直接使用，而不需要理解内部的作用机制(不需要理解放入袋子的物品是如何排布的)

下一升级，我们加入了 sentinel 节点。它是为了解决，空节点的插入问题。如果没有它，我们还需要对 first 进行分类讨论。而 sentinel 的出现，引入了一个 invariant，first 可以用稳定的 sentinel.next 替代。而不用讨论 first 是否非空。

接下来的升级，是为了进一步解决 Last 的操作问题，我们把它升级为了 DLList 双向的链表，同时拥有了两个 invariant 指代 first 和 last。但是这还是没有改善 get 和 insert 的效率。 为了改善 get 的效率，我们很自然就会想到 Array 的高效访问性能，但是问题是它是固定长度的，为了使其能够不断添加元素，一个非常自然的想法就是，元素放满了，就新建一个大的 Array 然后把原来的放入。这就是 ALList 由于我们是基于 Array 实现的，我们改善了 get，但是 insert 依旧 O(n)O(n) 的时间复杂度。

然后开始讨论 interface 和 polymorphism 的问题。也就是作为一个上层的 ADT，我们只需要给出我们需要的方法即可，不论是 SLList，DLList 或者 ALList，它们都是 List 的具体实现。

这部分在 review的时候，我才发现其精妙。

原始数据结构 →\to 封装 →\to invariant →\to 统一行为 →\to interface & polymorphism。

具体的课程知识点路径就是：

原始 intList →\to 封装为 SLList →\to 添加 sentinel 引入 invariant →\to DLList →\to ALList →\to 多种实现，引入 interface 整合，polymorphism 理念。

接下来学的 ADT 是 Disjont Union，这个 ADT 只关心哪些元素属于同一个集合，核心方法就是：

  • connect() 把两个元素加入同一个集合
  • isConnect() 判断两个元素是否属于同一个集合。

这里有一个非常核心的想法，就是我们可以把元素映射为数字，所有很自然的想法就是我们可以用 Array 的 index 代表元素。当然这是为了简化讨论。

假如一个 Array 的 index 就是元素，那很自然的想法就是对应的值就代表元素所属的集合。这个实现的特点就是 isConnect 性能非常好，所以叫 Quick Find。但是 connect 需要遍历修改，所以复杂度是 O(n)O(n)。复杂度的来源就是因为我们需要知道每一个元素所属的集合。所以我就升级这一部份，我们不需要知道每一个元素所属的集合，我们只需要确定它们来自同一个集合即可。这里也引出了 tree 的结构。也就是 connect 两个元素，我们只需要修改它们的父节点即可。所以 Array 只存储每个元素的父节点。如果两个节点来自同一个 root，则视为同一个集合。当然这里合并的规则还需要基于图论的知识，我们需要维护树的深度，小树需要挂载大树下面，才能保证复杂度。

这里我们会用到一个辅助函数 find()，它用来找到一个元素的 root。我们发现，多次调用 find()，意味着我们需要重复找，即时我们已经查询过同一个节点了。所以我们的改进想法就是，缓存已经 find() 过的路径。也就是假设路径是 A -> B -> C -> D，那我们就可以在探索的过程，顺便将 A，B，和 C 的父节点都设置为 D。

当然我一开始学的时候非常疑惑，明明我们探索的顺序是 ABCD，前面的节点都没有接触到 D，为啥可以直接设置呢？但是没有很好地理解递归。这里递归实现的话，find 返回 root 节点。然后直接递归到 C，返回 D，内部调用的对象的 root 等于 find() 调用对象父节点即可。pseudocode 如下：

private GraphNode find(GraphNode N) {

    if (N.parent == null) {
        return N;
    }

    N.parent = find(N.parent);
    return N.parent;

}

然后就是一个小的优化：合并 size 数组。

整体的知识路线就是：

Quick Find：set = [0, 1, 2, 3]，set[i] 表示元素 i 属于集合 set[i]。

升级：Quick Union：set = [0 , 1, 2 , 3]，size = [1 ,1 ,1 ,1]。set[i] 表示元素 i 的父节点是 set[i] 为这个树包含元素个数。

再升级：合并数组：set = [0, 1, 2, 3]。对于 size[i]，如果 i 大于零，则同上。如果 i 小于零，这说明是 root，代表树的 size。

接下来我们学习的是 BST。

为了构造它，我们需要保证对象是可以比较的，也就是我们需要实现比较方式。整体用对象实现，我们需要实现一下几个基本方法： 1. get() 2. insert() 3. remove()

这里 get 和 insert 是比较简单的，难的是 remove，它需要重新整理删除节点下面连接的东西。这里一个朴素的想法就是，我们删除一个节点，就是返回这个节点消失后的 subtree。这里需要推理的就是需要那一个节点作为新的 root。我们分类讨论：

  1. 没有 child，自然就是 null
  2. 单个 child，就是 child
  3. 两个 child，新的 root 需要大于左边的所有节点，小于等于右边的所有节点。很自然的就是选择左边最大的元素或者右边最小的。位置上看，就是左侧最右边或者右侧最左边。

接下来的问题是树本身的性质导致的，就是如果每次添加的都是递增或者是递减的，BST 的性能会退化，为了解决这个问题。接下来升级为了 B tree，它的特点是将节点升级为了区间，不限制子节点的数量。然后核心操作是 split，然后有一种特殊的 B tree 是 2-3 tree 就是最多三个子节点的树。特别的，它 split 后和 LLRB 是一一对应的。而前者可以维护一棵 balance 的 BST。所以我们实现 LLRB 即可。

LLRB 的实现非常复杂，需要维护 LLRB 的合法性。(通过 roate 和 flip)，无论如何，我们得到了一个良好的数据结构。

然后就是 Hash Table 和 PQ 这两个刚学完，就不回顾了。
